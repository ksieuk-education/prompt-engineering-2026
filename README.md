# prompt-engineering-2026

## Агентский театр

Четыре персонажа разыгрывают одну из двух пьес. Драматург сначала пишет план,
затем на каждом ходу отдельная модель в роли актёра отвечает на услышанное.
Финал зависит от четырёх голосов.

| Код постановки | Персонажи | Предмет спора |
| --- | --- | --- |
| `extra` — «Лишний персонаж» | Тони Старк, Гермиона Грейнджер, Чендлер Бинг, Барби | Кого оставить, если гарантированы только три выхода? |
| `lab404` — «Лабораторная № 404» | Профессор Сошников, Чендлер, Гермиона, Барби | Кто может установить, чей опыт «настоящий»? |

Завязки, состав и ходы конфликта взяты из двух исходных
[сценарных заявок](references/).
Образ профессора в постановке вымышлен. Карточки, примеры интонаций и документы
терминала подготовлены для симуляции. Текст выступлений генерируется при запуске.

[Ноутбук лабораторной](LLM_Theatre.ipynb) открывает сохранённый спектакль,
показывает фактические ходы, найденную строку архива, голоса и фонограмму.
В [отчёте](REPORT.md) есть сравнение прогонов и разбор реплик.
В [каталоге спектаклей](examples/season/README.md) для каждой постановки доступны
текст читки, исходная импровизация, запись и субтитры. Ранее сыграны
[«Лишний персонаж»](examples/extra-revised/play.md) и [«Лабораторная № 404»](examples/lab404-edited/play.md).
С каждой пьесой хранятся план драматурга и журнал вызовов инструментов и ходов.
Ранние репетиции остались в `examples/extra`, `examples/extra-alt` и `examples/lab404`.

### Книги как свидетели

В новой серии Гермиона находит в «Бесприданнице» ремарку о монете, а Чендлер открывает у Чехова дом, в котором забыли Фирса. Второй актёр может перелистнуть страницу, выбрать соседнюю реплику и поправить первого. У реплик и ремарок есть ссылки на строки полного издания. После игры в досье можно проверить, что именно услышали остальные и чей голос мог изменить финал. [Три постановки, тексты и записи](examples/library/README.md) · [Досье «Лишнего персонажа»](examples/library/extra/dossier.md)

В библиотеке три полных текста из RusDraCor, 13 действий и 4 866 фрагментов. Поиск учитывает русские словоформы, имена говорящих, редкость слов и соседство реплик в пределах одного явления. При импровизации задачу и книгу задаёт сценарий, сам запрос и подходящий результат выбирает модель. В командной строке можно искать сразу во всех пьесах. Для просмотра, оценки поиска и сравнения готовых спектаклей достаточно базовой установки Poetry.

~~~sh
poetry run theatre-library search 'Фирс заперто уехали'
poetry run theatre-library open garden:1468 --radius 3
poetry run theatre-library bench
poetry run theatre-library dossier examples/library/lab404
poetry run theatre-library compare examples/library/control examples/library/extra
~~~

Новый запуск `poetry run theatre extra` подключает библиотеку автоматически. Флаг `--no-library` позволяет повторить опыт с тем же планом без неё. [Происхождение изданий](src/agent_theatre/data/library/README.md) · [Ранги результатов для 18 вопросов](examples/library/benchmark.json)

### Запуск

Нужны Python 3.11+, Poetry 2 и [Ollama](https://ollama.com/).
В одном терминале запустите `ollama serve`, если сервер ещё не работает.
В другом, из корня репозитория:

~~~sh
ollama pull qwen2.5:7b
ollama pull hf.co/unsloth/gemma-3-4b-it-GGUF:Q4_K_M
poetry install
poetry run pytest -q
poetry run theatre extra --turns 4
poetry run theatre lab404 --turns 4
~~~

После загрузки обе модели работают на машине пользователя.
[Веса Gemma из Hugging Face](https://huggingface.co/unsloth/gemma-3-4b-it-GGUF).
`--turns` задаёт число реплик в каждой из первых трёх сцен (от 4 до 10,
по умолчанию 6). В четвёртой у каждого героя один решающий ход.
Обычный прогон создаёт новую папку в `runs/`. Чтобы выбрать другую,
передайте `--out путь/к/новой-папке`. Уже существующие результаты защищены
от перезаписи.

Для локального GPT-драматурга и редактора загрузите отдельную модель.
Первой командой ниже после загрузки создаётся план и разыгрывается пьеса.
Второй запуск использует тот же план «Лишнего персонажа», что и контрольная репетиция.

~~~sh
ollama pull gpt-oss:20b
poetry run theatre lab404 --planner gpt-oss:20b --editor gpt-oss:20b --turns 4 --seed 404
poetry run theatre extra --plan-from examples/extra --turns 6 --seed 17
~~~

### Ноутбук и звук

~~~sh
poetry install --with notebook
poetry run jupyter execute LLM_Theatre.ipynb
~~~

Откройте `LLM_Theatre.ipynb` в Jupyter или VS Code и выполните все ячейки с чистого ядра. Ноутбук включает исходники Python, оба сценария, библиотеку TEI, журналы и четыре полные записи. Для просмотра достаточно самого файла и окружения Python. В настройках `SCENARIO` выбирает `extra` или `lab404`, а `MODE = "replay"` открывает готовую постановку. В разделе архива можно выбрать дополнительный вариант по имени папки через `VARIANT`.

При `MODE = "live"` ноутбук заказывает GPT-OSS новый макроплан, разыгрывает четыре действия на Qwen и Gemma и с включённым `SYNTHESIZE` записывает WAV и WebVTT в новом подкаталоге `runs/`. В терминале с работающей Ollama и скачанными моделями тот же путь запускается с помощью `THEATRE_MODE=live poetry run jupyter execute --timeout=1800 LLM_Theatre.ipynb`. Быстрый просмотр и проверка сохранённых результатов доступны без Ollama и PyTorch. Для нового синтеза используется [Silero v5.6](https://github.com/snakers4/silero-models#v5).

Группа `audio` рассчитана на Python 3.11–3.14. Проверено на 3.13.

~~~sh
poetry install --with notebook,audio
poetry run theatre-audio examples/season/extra-058 --out runs/extra.wav --captions runs/extra.vtt
~~~

При первой записи загружаются веса Silero в кэш PyTorch. Программа сверяет SHA-256
перед открытием пакета. Для уже скачанного файла есть `--model путь/к/v5_6_ru.pt`.
Генератор озвучивает версию из `edition.json`, если постановка прошла финальную
вычитку. Далее по приоритету идут автоматическая читка `reading.json` и исходные
ходы из завершённого журнала. Результат — моно WAV 48 кГц. В каталоге лежат
сжатые копии AAC и файлы WebVTT с именами говорящих. Пол и голос заданы в
карточке роли и копируются в журнал. Гермиона и Барби имеют разные женские
голоса, Тони или профессор и Чендлер — разные мужские. Пятый голос читает ремарки.
При монтаже выравнивается громкость, а перед ответом на вопрос оставляется более короткая пауза.

Чтобы сыграть, отредактировать и озвучить новый вариант локально:

~~~sh
ollama pull gpt-oss:20b
poetry run theatre extra --plan-from examples/extra --no-editor --turns 4 --seed 17 --out runs/my-extra
poetry run theatre-reading runs/my-extra --model gpt-oss:20b
poetry run theatre-audio runs/my-extra --captions runs/my-extra/play.vtt
~~~

На первом шаге `--no-editor` оставляет проверку отдельных реплик правилам Python.
Без флага смысловой редактор (по умолчанию первая актёрская модель) также проверяет
черновики во время игры. Читка на втором шаге видит целую сцену, включая уточнения
после вопроса, голоса и предыдущий разговор. Программа проверяет порядок реплик
и берёт решения о голосовании из исходных ходов. В сохранённых примерах можно
сопоставить обе версии по номеру хода.

Для читки можно положить в папку прогона `directions.json` с режиссёрским заданием
на каждый нужный ход. Ключи — номера ходов строками. После автоматической читки
редактор может подать JSON правок вида `{"3": {"line": "Что показала проверка?"}}`
командой `poetry run theatre-reading runs/my-extra --edits правки.json --credit "Имя редактора"`.
Появятся отдельные `edition.md` и `edition.json`. В каталоге доступны и исходная,
и автоматическая, и вычитанная версии. Для постановки 307 сохранён также звук до
вычитки. [Сравнить записи и тексты](examples/season/README.md)

### Как устроена постановка

- `src/agent_theatre/data/` содержит две независимые постановки и карточки пяти ролей. Роль узнаёт личный мотив из своей карточки, а позицию партнёра — из сказанной им реплики.
- `engine.py` запрашивает у драматурга названия, сценические открытия и задачи четырёх сцен. Режиссёр отдаёт ход адресату, отмеченному актёром в ответе. После пяти пропущенных ходов приоритет получает тот, кто дольше молчал. В финале каждый голосует один раз.
- Во второй и третьей сценах исследователи могут сами сформулировать запрос к `search_archive`. `archive.py` ищет по словам заголовка и строкам локальных файлов, учитывая общие префиксы русских слов. Результат содержит точный отрывок и номер строки. Карточки находятся у прочитавшего их актёра. Другие слышат только его реплику.
- Перед ходом актёр может вызвать `recall_line` для поиска по репликам конкретного партнёра. Результат содержит текст, действие и номер исходного хода. `test_ballot` проверяет, сколько голосов нужно для пересмотра или выбора одного имени. Актёр задаёт предполагаемое число сторонников, терминал использует те же пороги, что в финале. Аргументы и результат обоих инструментов записываются в журнал.
- У каждого хода есть намерение и исполнение. Первым вызовом актёр выбирает адресата, архивную опору и, в финале, голос. Вторым вызовом та же модель произносит реплику. Явное обращение по имени уточняет адресата. Если режиссёр дал слово третьему участнику, адресат всё ещё увидит ожидающий ответа вопрос в своей сцене.
- Каждое действие ставит перед игроками конкретную задачу. В третью и четвёртую сцены переходят последние публичные доводы участников предыдущей сцены. Личные архивные карточки остаются у прочитавших их персонажей.
- Перед публикацией `rehearsal.py` проверяет черновик на близкий повтор, незавершённую фразу, грамматический род говорящего и адресата, утверждения о родственниках вне карточки и явное расхождение с ценой самовыдвижения. Редактор сверяет прямой вопрос, карточку, контекст, обоснование голоса и черновик. Замечание о противоречии опирается на дословные цитаты. Новые слова пишет исходный актёр. Журнал сохраняет отклонённый текст, причину и номер хода.
- В финале у каждого решения есть стандартная короткая формулировка для регистрации. Решение и личное обоснование выбирает модель. Голос виден на табло даже тогда, когда персонаж высказывается уклончиво.
- Четыре возражения меняют правило терминала. Три или четыре совпавших имени выбирают персонажа по условию текущей пьесы. Иначе время истекает. Последствия этих вариантов заданы постановкой, конкретный выбор делают модели.
- `llm.py` валидирует структурированные ответы, один раз запрашивает исправление при ошибке и явно прерывает неудачный прогон.

По умолчанию план и смысловая проверка поручены первой актёрской модели.
Модели актёров задаются `--model-a` и `--model-b`.
В `examples/lab404-gpt` план написала локальная
[GPT-OSS 20B](https://ollama.com/library/gpt-oss:20b).
Для облачного драматурга задайте `OPENAI_API_KEY` и `--planner openai/ID_МОДЕЛИ`.
При локальных актёрах и редакторе в OpenAI Responses API уходит запрос драматурга.
Другой адрес Ollama задаётся через `--ollama-url`, начальное зерно через `--seed`.

### Что сохраняется

- `play.md` — текст пьесы, ремарки, объявление терминала и развязка.
- `plan.json` — план драматурга, записанный до первой реплики.
- `trace.jsonl` — последовательность событий, модели актёров, причины выбора говорящего, поисковые запросы, найденные файлы и решения героев. При сбое остаётся журнал с точкой остановки.
- `reading.md` и `reading.json` — текст литературной читки и её привязка к исходному журналу по контрольной сумме. В журнале инструментов всегда цитируется именно то, что актёры слышали во время импровизации.

Тесты в `tests/` работают без весов и сети. Из Python генератор вызывается через
`agent_theatre.engine.perform` с обработчиком событий. Ноутбук запускает тот же
CLI через Python, поэтому сохраняет файлы в обычном формате проекта.
